# BRIEF_SPEC — 每日简报格式契约

> 面向：以后要为 `journal/*.md` 写解析器和评分器的人（见 DESIGN.md M4）。
> 本文档定义的是**格式契约**，不是写作指南；写作指南在
> `prompts/daily_brief.md`。两者应保持同步，但改动动机不同：改这份文档
> 要问"解析器会不会炸"，改那份要问"分析质量够不够"。

## 核心链条

简报存在的意义只有一条链：**可溯源 → 可解析 → 可评分 → 可证伪**。

- 可溯源：每条陈述标注 `source-id`（事实层）或推断依据（判断层）。
- 可解析：结构固定，脚本不用 NLP 就能切出字段。
- 可评分：情景推演与"我的立场"给出可判定的触发条件、概率、认错条件。
- 可评分依赖可证伪：模糊表述（"偏强""可能上涨"）无法判定对错，格式层
  面直接禁止它们进入文档。
- 任何一个环节断掉，M4 打分系统就失去输入——这是七个 section、封闭
  词表、双层标注存在的唯一理由，不是为了好看，是为了能被公正秋后算账。

## 标注体系：事实层与判断层

正文每一句实质性陈述必须标注 `[来源: source-id]`（事实句）或
`[推断: 基于 xxx]`（判断句），二者语义不同，解析器需分别处理：

- `[来源:]` 是**转述**——内容可在对应 document 中找到直接表述，解析器
  用它做一致性校验（`sources` front-matter 与正文引用是否对齐）。
- `[推断:]` 是**综合判断**——材料里没有任何单一来源这样明说，`xxx` 是
  推断依据的自由文本，不强制结构化，但要求非空、非套话（"综合判断"这
  类空话视为格式弱校验失败）。

判断层为什么强制：简报的价值是"你自己怎么判断"，纯转述没有价值——脚本
自己就能拼接 document。判断被 `[推断:]` 隔离出来，是为了让 M4 评分器
只对判断层打分：事实句对错是校对问题，判断句对错才是"分析质量"问题，
混在一起标注评分器就无法区分这两类性质不同的错误。

## Front-matter 字段定义

```yaml
---
date: 2026-07-10          # ISO 8601 日期，简报覆盖的交易日
session: intraday          # 枚举: premarket | intraday | postmarket | closed
sources:                   # 本篇实际引用到正文的 source-id 列表
  - id: newsletter-a        # 抽象 id，不是真实刊物名（见 DESIGN.md D2）
    published: 2026-07-09
  - id: research-b
    published: 2026-07-08
status: draft               # 枚举: draft | reviewed | scored
version: 1                  # 见下方"同日多版本"规则
---
```

- `date` + `session` 共同构成一份简报的"时间坐标"，解析器据此在时间轴
  上定位。
- `sources[].id` 必须与正文 `[来源: source-id]` 标注**完全对齐**——
  解析器可以用它做一致性校验：正文引用了 front-matter 没声明的 id，或
  声明了却从未引用，都应判为格式错误。`[推断:]` 不受此约束，因为它
  不指向某一个具体 document。
- `status` 是外部工作流状态机的钩子（生成 → 人工/机器复核 → 打分完成），
  本文档只定义取值范围，不定义状态机本身。
- `version` 见下条。

## 同日多版本：version 递增规则

同一个 `date` + `session` 组合允许多次生成简报（例如盘中信息更新后重跑）。
规则：

1. 同一 `date` + `session` 下，`version` 从 `1` 开始，每次重新生成
   **严格 +1**，不得跳号，不得复用旧编号。
2. 旧版本文件不删除、不覆盖——落档遵循 DESIGN.md D6（一切落地为文件），
   每个 version 是独立文件，文件名或路径需体现 version（具体命名方案由
   落档脚本决定，本文档只锁定"version 单调递增、旧档不可变"这一契约）。
3. 解析器/评分器在同一 `date`+`session` 下如果发现多个 version，默认
   应取 `version` 数值最大者作为"当前有效简报"，但历史 version 仍需可
   被单独读取——评分器需要对比"早盘判断"和"盘后修正版"的差异。
4. **版本对比 = M4 前身**：同一天若用不同 prompt 版本或不同模型对**同一批
   输入材料**重新生成，也会落出 `-2`/`-3` 后缀（触发原因是"换了生成
   配置"而非"信息更新"，其余规则同上）。这类同数据、不同生成配置的
   对比，是最小形态的 prompt eval——不必等 M4 的真实价格结果，仅靠对比
   "我的立场"具体程度、认错条件是否离散、`[推断:]` 密度，就能初步判断
   哪个版本分析质量更高，值得在落档时保留而非覆盖。

## 七个 section 的存在理由

| Section | 存在理由 |
|---|---|
| 一句话结论 | 给评分器一个最小可判定单元：一句你自己的判断，"方向 + 触发条件"就是日后核对"说中了没有"的最小颗粒度。 |
| 关键数字 | 结构化表格而非散文，是为了让解析器不做 NLP 就能抽取 `数字/口径/来源/YoY/QoQ` 五个字段做交叉校验。 |
| 论点与证据 | 按论点而非按来源组织，逼迫模型先做跨源对齐再下笔；强制 `[来源:]`/`[推断:]` 保证"可溯源"不断裂，解析器按标注类型即可分流事实与判断。 |
| 我的立场 | 判断层的核心可评分单元：倾向、置信度、最强反方、认错条件、时间框架五项固定结构，解析器可直接抽取做"该立场后来站住了没有"的核对。 |
| 情景推演 | 固定列 `情景/概率/触发条件/影响`，概率合计=100 是可编程校验的硬约束，触发条件禁止点位是为了让"对/错"由结构性事件判定，而不是被行情噪音在几美分内判定。 |
| 存疑与矛盾 | 保留分歧本身也是数据——评分器需要知道"这天来源打架了"，而不是被悄悄抹平的假共识误导。 |
| 明日观察清单 | 面向未来的可证伪清单：每条都是"下一次简报可以直接勾对错"的检查项，是连接连续多日简报的锚点。 |

## 我的立场：五项结构

`## 我的立场` 每条固定五项，缺一即为格式错误：

- **倾向**：方向性判断，词表内外均可，但必须是明确方向，不能模糊。
- **置信度**：`低/中/高` 三选一，禁止用百分比或形容词代替。
- **最强反方**：最强反面论据，无论来源是否明说，都必须具体列出并标注
  `[来源:]` 或 `[推断:]`。
- **认错条件**：出现什么具体可观察的数据/事件就放弃这个立场，**必须是
  离散、可判定的事件**（而非"如果情况变差"这类连续/模糊表述）——与下一节
  "为何禁止点位"同一条论证链：连续变量可被抵赖，离散事件可被核验。
- **时间框架**：这个立场适用的窗口。

## 为什么禁止点位、只给情景

价格点位是随时间连续变化的连续变量，"说对了没有"依赖于事后你选择哪个
时间窗口去核对——这让评分永远可以被抵赖。情景推演换成
`Bull/Base/Bear` + 结构性触发条件（例如"跌破前低""突破前高确认放量"），
把待评分对象从"连续数值"换成"离散事件是否发生"，评分器只需要在触发
条件发生的那天检查一次"发生了/没发生"，不需要理解价格、不需要处理噪音，
判定结果不会因为回看窗口选取不同而改变。这也是分析工具和喊单工具的
分界线——本系统的输出目标是"可被秋后算账的判断"，不是"操作建议"。

## 机器依赖：标题不能改

`## 一句话结论` 与 `## 情景推演` 这两个标题被 `scripts/build_brief.py`
的 `previous-brief` 提取正则依赖，用于把上一份简报喂回下一次生成、构成
连续多日的对质链。改动标题文字（哪怕只改标点）等于让正则静默失配、
丢失连续性检查——这是 `prompts/daily_brief.md` 把它们标记为"一字不动"
的原因。

## 封闭词表（全文）

盘面/资金状态描述**只能**从以下取值中选择，不得同义替换或自造：

```
机构派发 | 主力吸筹 | 主力散户背离 | 全档抛压 | 全档吸金 | 缩量观望
```

回调分级**只能**从以下四档中选择：

```
1-震荡 | 2-获利了结 | 3-恐慌 | 4-风险传染
```

材料信息不足以映射到词表任何一项时，唯一合法输出是 `信息不足以分级`。
解析器应把词表外的任何取值一律视为**格式错误**，而不是尝试模糊匹配或
容错纠正——容错本身会破坏"可评分"这一环（模糊词无法被判定对错）。
